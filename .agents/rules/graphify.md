## graphify

This project has a graphify knowledge graph at graphify-out/. If it exists, you can use it to answer codebase and architecture questions. The graph is generated from the codebase and provides a structured view of the relationships between files, classes, functions, and other entities. Always prefer graphify queries over raw grep or reading files directly, as the graph is scoped and filtered to the relevant context. If graphify-out/graph.json does not exist, you can ask user to generate it with `graphify .` (AST-only, no API cost).

Rules:
- For codebase or architecture questions, when `graphify-out/graph.json` exists, first run `graphify query "<question>"` (CLI) or `query_graph` (MCP). Use `graphify path "<A>" "<B>"` / `shortest_path` for relationships and `graphify explain "<concept>"` / `get_node` for focused concepts. These return a scoped subgraph, usually much smaller than `GRAPH_REPORT.md` or raw grep output.
- If graphify-out/wiki/index.md exists, navigate it instead of reading raw files
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context
- After modifying code files in this session, run `graphify update .` to keep the graph current (AST-only, no API cost)
